## 토큰 방식 인증
- 기존 세션 인증 방식
  - 각 사용자마다 세션 객체를 생성
  - 즉, 사용자가 많아지면 자원 소모량 및 비용이 커짐
- 토큰 인증 방식
  - 서버는 아무것도 저장하지 않음
  - 사용자 정보를 토대로 토큰을 만들어서 사용자에게 전달.
  - 서버는 토큰이 위조 되지 않았는지만 확인하면 된다.
- 즉, 규모가 크다면 토큰 인증을 사용
  - 인증 계층에서 낭비되는 메모리 감소
  - 서버가 Stateless 하도록
- 단, 사용자의 규모가 작다면
  - 간편하고 관리 기능도 풍부하기에 세션 인증 방식이 이점이 많음 
## Scale Out
  - 서버 인스터스를 추가하는 전략 (수평적)
  - Scale up : 서버 성능을 높이는 전략 (수직적)
  - Scale Out 환경의 특성
    - Load Balancer
    - 메모리 비공유 (독립적 존재)
    - Auto Scaling (동적 인스턴스 증감)
  - Scale Out 환경에서의 세션 인증
    1. Sticky Session
    2. Session Clustering
    3. External Session Storage

## 인증 관련 보안 문제 3가지
1. Hijacking
2. Escalation
3. 내부자 위협

## 세션 방식 인증 장점
- 보안이 중요하다면 세션 인증 방식을 사용
  - 서버가 제어권을 가짐
  - 보안 사고 감지 시 세션 즉시 비활성화 가능
  - 토큰의 경우 서버는 위변조 여부만 검증하기에 탈취 여부를 모름
    - 만료 시간 이전까지 무효화 불가
- 개발 복잡도 저하

## 토큰 방식이 주는 성능의 영향
- 응답시간
  - 토큰 서명 검증 연산 비용이 포함
- 즉, 외부 저장소 조회가 필요 없기에 성능이 중요할 경우 사용하기 좋다.

## 어느쪽이 우수한 인증 방식이 아니다. 프로젝트에 맞는 인증 방식을 사용하자

- 현재까지 해본 프로젝트에서는 토큰 인증방식이나 세션 인증 방식을 적용해본 경험이 없다.
- 앞으로 할 프로젝트에서는 어떤 인증 방식을 적용할 것인가에 대하여
  - 솔직히 무엇 하나를 정해서 적용하겠다! 라고는 못할 것 같다.
    그때그때 상황을 보고 필요한 인증 방식을 선택할 것 같다.
